Data we use

Only this run’s published grid forecasts (horizonHours 6 or 24) and its own observations. No actuals from other runs, no future values, no cross-run caches. Never commit carbon values from a real run.

Source: the grid API endpoint for the current run only. The planner calls forecast(area, now) every simulated hour; beyond 24 h it blends the last forecast day’s mean with a 10% risk premium.

How the scheduler works

Blocks. For each workload the planner reserves a time block [start, end) and holds quota (vCPUs, VMs, GPU cards) for the whole block—stopped VMs still count. This is because the platform keeps quota for stopped VMs.
Run hours. Inside a block the VM runs only in the cleanest hours (lowest forecasted g/kWh) and is stopped in the dirty ones. Stopping draws zero electricity but keeps the quota reserved. Checkpointable jobs can be paused through dirty hours and resumed later without re-running boot or input staging.
Why pause? A block lets the planner wait for a cleaner window without burning quota on a VM that would run in dirty hours. The trade-off: longer blocks use quota longer, but running in dirty hours wastes carbon.
